## Устойчивость скролл-видео на Vercel — 24 октября 2026

По сообщению о периодическом зависании проверен именно опубликованный сайт
https://arka-123-gold.vercel.app/. MP4 доступен (13 729 320 байт), сервер
поддерживает Range / 206; moov в начале, все 289 кадров ключевые. После полной
загрузки в браузере прошли скролл вперёд/назад и переходы между главами,
ошибок консоли нет. Сам периодический сбой в этой проверке не воспроизведён.

В прежнем коде seek требовал readyState >= 2 и повторялся только при scroll,
loadeddata и seeked. При metadata-only preload и восстановлении буфера это
могло оставлять ролик без повторной синхронизации. Контроллер `scroll-video.ts`
разрешает seek после metadata (readyState >= 1), реагирует также на canplay,
progress и durationchange и сохраняет только последнюю позицию скролла.
При возврате к вкладке/странице геометрия и позиция пересчитываются.

При ожидании видна загрузка; через 12 секунд без готового кадра — возможность
повторить, при ошибке — та же кнопка. Retry сбрасывает зависший seek через load()
и восстанавливает текущую позицию. Ошибка больше не удаляет видео и не схлопывает
sticky-секцию посреди скролла; сохраняются постер, главы и геометрия.
Reduced motion и высота <=500 px по-прежнему дают компактную статичную сцену.
Новые медиа не генерировались. Добавлено 10 регрессионных тестов; общий набор — 27.
Изменения подготовлены в рабочей копии; публикация на Vercel ещё не выполнялась.

## Боковое меню на телефоне — 23 октября 2026

Причина последующего рывка найдена по кадрам: нативный фокус на кнопке
в сдвинутой панели прокручивал dialog по горизонтали на 380 px, компенсируя
transform. У dialog теперь overflow: clip вместо hidden — это исключает
программную горизонтальную прокрутку; вертикально прокручивается сама панель.
Проверены промежуточные позиции левого края 440 → 364 → 297 → 196 → 135 → 60 px
при неизменном dialog.scrollLeft = 0 (Chrome, viewport 440 px).

После замечания об анимации добавлено плавное закрытие: открытие 360 ms,
закрытие 280 ms, затемнение синхронно меняет прозрачность. Нативный dialog
остаётся открытым и блокирует фон до окончания ухода панели. Используются
CSS transitions, поэтому закрытие посреди открытия продолжается из текущего
положения. Переход по разделу отложен до закрытия, без скачка фона под панелью.
Состояния — closed/opening/open/closing, завершение по transitionend с резервным
таймером 400 ms; при reduced motion переходы отключены.

По запросу бургер на экранах до 900 px открывает белую панель справа
с салатовыми акцентами вместо прежнего выпадающего списка. Ширина — до 380 px,
на узких телефонах 88vw; фон затемнён, страница под меню не прокручивается.
Внутри ссылки на разделы, CTA к заявке, телефон, почта и адрес. Панель прокручивается
на невысоких экранах. Закрытие по крестику, фону, Escape или выбору раздела;
при переходе на десктопную ширину также закрывается. Нативный dialog в портале
удерживает фокус внутри, после закрытия фокус возвращается к бургеру.
Поддержан reduced motion. Файлы — `SiteHeader.tsx`, `mobile-navigation.css`, `site.css`.

для хостинга — OPENROUTER_API_KEY / OPENROUTER_MODEL или ARKA_CHAT_ENV_FILE.
Не публиковать ключ, не переносить его в исходники и не печатать в логах.
